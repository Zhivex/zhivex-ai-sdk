Add an experimental MCP server at `@zhivex-ai/core/mcp-server` and `@zhivex-ai/sdk/mcp-server`. It exposes local tools and agents to MCP clients over Streamable HTTP and newline-delimited stdio, pinned to protocol `2025-11-25`. Tools and agent registrations that require approval are not executed; an in-run approval pause is returned as `APPROVAL_REQUIRED` and is not resumed. Synchronous tool failures, `isEnabled`, guardrails, authentication, and reading the HTTP body stay inside the call deadline. Agent progress is not awaited after that deadline, and a throwing `toRunInput` returns `AGENT_FAILED`. Closing the server aborts in-flight HTTP calls. Numeric and string JSON-RPC ids are tracked separately. Oversized HTTP and stdio responses stay within the configured byte cap, and a fatal stdio read or stdin EOF closes the session. A browser `Origin` is rejected unless `allowedOrigins` lists it. HTTP sessions are capped and expire when idle. `timeoutMs` above the 32-bit timer range is rejected, and an HTTP timeout cannot outlive the server call limit. Closing the server during authentication returns 503. `authenticate` receives an `AbortSignal`. `DELETE` aborts in-flight calls. Each session has a concurrency cap, duplicate in-flight ids are rejected, and stdio holds that slot until the response is written. Authentication, the body read, and the call share one HTTP deadline. Schema refinements that throw, and a throwing `toDefinition`, stay inside a tool error. Cancelling an SSE response does not surface an unhandled rejection. The Node stdio binder is `@zhivex-ai/sdk/mcp-server-stdio`; browser bundles resolve a stub that throws. `MCP_SERVER_API_STABILITY_MANIFEST` classifies every runtime export as experimental.
